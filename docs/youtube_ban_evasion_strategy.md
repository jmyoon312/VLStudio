# YouTube 봇 탐지 시스템 대응 및 연좌제(Ban/Shadowban) 회피 운영 전략

본 문서는 Google/YouTube의 고도화된 디바이스 핑거프린팅, 행동 바이오메트릭스 분석 및 계정 연결 탐지 시스템을 우회하여 채널 연좌제 차단(Shadowban 및 영구 정지)을 방지하기 위한 ViraLoop Studio(VLStudio)의 핵심 보안 운영 전략을 정리합니다.

---

## 1. 아키텍처 핵심 설계: 역할 분리와 다중 격리

유튜브 연좌제 방어의 최우선 원칙은 **"계정 간의 구조적/네트워크적 연결 고리를 완전히 끊는 것"**입니다. 이를 위해 소유자 계정(TIN_CAN)과 관리자 계정(CAPTAIN)을 독립된 레이어로 분리하고 다중 격리 환경을 구축합니다.

### 1.1 계정 역할 분리 및 매칭 규칙
```mermaid
graph TD
    subgraph Owner Layer (TIN_CAN)
        O1["소유자 1 (TIN_CAN 1)<br/>LTE 모바일 IP (개별 격리)<br/>Ghosting (접속 배제)"]
        O2["소유자 2 (TIN_CAN 2)<br/>LTE 모바일 IP (개별 격리)<br/>Ghosting (접속 배제)"]
        O3["소유자 3 (TIN_CAN 3)<br/>LTE 모바일 IP (개별 격리)<br/>Ghosting (접속 배제)"]
    end

    subgraph Management Layer (CAPTAIN)
        C1["관리자 1 (CAPTAIN 1)<br/>전용 주거지/고정 IP<br/>최대 3~5개 채널 위임"]
    end

    subgraph Brand Channels
        BC1["브랜드 채널 A"]
        BC2["브랜드 채널 B"]
        BC3["브랜드 채널 C"]
    end

    O1 -->|소유/생성| BC1
    O2 -->|소유/생성| BC2
    O3 -->|소유/생성| BC3

    BC1 -->|권한 위임| C1
    BC2 -->|권한 위임| C1
    BC3 -->|권한 위임| C1
```

*   **1-Channel-1-Owner (1채널 1소유자) 규칙**:
    *   모든 브랜드 채널은 단 하나의 독립된 소유자 계정(`TIN_CAN`)에 의해 생성되고 소유되어야 합니다.
    *   하나의 소유자 계정으로 여러 브랜드 채널을 관리하는 것은 절대 금지됩니다. (소유자 계정 정지 시 연동된 모든 채널 동시 차단 방지)
*   **권한 위임 및 관리자 리스크 제어**:
    *   브랜드 채널을 생성한 직후, 실제 업로드를 수행할 관리자 계정(`CAPTAIN`)에 관리 권한을 위임합니다.
    *   **위험 분산 한도(Risk Containment Limit)**: 하나의 `CAPTAIN` 계정에는 **최대 3~5개의 브랜드 채널**만 위임합니다. 특정 관리자 계정이 탐지되어 차단되더라도 손실을 최대 3~5개 채널로 한정 짓기 위함입니다.
*   **소유자 계정 고스트화 (Owner Account Ghosting)**:
    *   권한 위임이 완료된 소유자 계정(`TIN_CAN`)은 더 이상 기기 로그인이나 영상 업로드에 사용하지 않고 **"유령 상태"**로 방치합니다.
    *   활동이 없는 계정은 탐지 표면(Attack Surface)이 최소화되므로 안전하게 소유권을 유지할 수 있습니다.
*   **네트워크 격리 (LTE Proxy Enforcement)**:
    *   소유자 계정의 모든 초기 설정 및 위임 행위는 반드시 **개별 LTE 모바일 프록시(공유 클래스 IP)** 환경 하에서만 수행되어야 합니다. PC 일반 가정용 Wi-Fi나 VPN 대역은 즉시 동일 주체로 그룹화(Clustering)되어 탐지됩니다.

## 2. 하이브리드 업로드 프로세스 (디바이스 핑거프린트 분산)

계정 생성 초기에는 탐지 필터가 매우 민감하게 작동합니다. 인간적인 사용 흔적과 물리적 디바이스 신뢰도를 누적하기 위해 모바일 기기(실제 스마트폰)와 자동화 브라우저(VLStudio)를 결합한 하이브리드 방식을 적용합니다.

```
[단계 1: 폰 업로드] (1~6개 영상)
  - 예비 LTE 폰에서 직접 로그인
  - 실제 카메라/마이크 핑거프린트 및 물리 터치 누적
  - 유튜브 시스템 내 "신뢰할 수 있는 인간 사용자"로 등록
       ▼
[단계 2: 하이브리드 과도기] (7~15개 영상)
  - 폰 업로드와 VLStudio 보안 브라우저 자동 업로드를 교대로 진행
  - 디바이스 신뢰도가 자연스럽게 PC 환경(VLStudio)으로 이식됨
       ▼
[단계 3: 100% 자동화] (16개 영상 이후)
  - 스마트폰 사용 배제
  - VLStudio의 격리된 브라우저 세션을 통해서만 완전 자동화 운영
```

### 2.1 단계별 세부 가이드
1.  **예비 스마트폰 업로드 단계 (초기 신뢰성 구축)**:
    *   계정 생성 후 최초 5~6개의 동영상은 PC를 사용하지 않고, 공인 IP가 수시로 바뀌는 모바일 LTE 환경(스마트폰)에서 직접 유튜브 앱/스튜디오 앱을 통해 업로드합니다.
    *   이 시기에는 모바일 자이로스코프, 터치 스크린 좌표 변화, 실제 네트워크 지연 시간 등의 물리 데이터가 구글에 전송되어 계정의 신뢰도 등급(Trust Score)을 확보하게 됩니다.
2.  **하이브리드 과도기**:
    *   폰 업로드와 VLStudio 보안 브라우저를 번갈아 사용하면서, 유튜브 시스템이 "이 사용자는 모바일 기기와 PC 브라우저를 교대로 사용하며 작업한다"는 세션 연관을 학습하게 만듭니다.
3.  **안정기 (100% VLStudio 자동화)**:
    *   충분한 신뢰도가 누적된 이후에는 모바일 로그인을 로그아웃하고, 오직 VLStudio의 안티 디텍션 브라우저 세션만을 이용하여 완전 자동 업로드를 수행합니다.

## 3. 7일 계정 워밍업 시퀀스 (Warmup Cycle)

신규 채널에 즉시 비디오를 올리거나 관리자 권한을 행사하는 행위는 스팸 봇 필터에 즉각 걸립니다. 최소 7일간의 행동 기반 워밍업 기간을 준수해야 합니다.

### 3.1 워밍업 단계 액션 플랜
*   **1일차**: 소유자 계정 생성 즉시 관리자(`CAPTAIN`) 계정으로 권한 위임을 신청하고 승인합니다.
*   **2일차 ~ 7일차 (매일 30분~1시간 자동/수동 실행)**:
    *   유튜브 스튜디오에 바로 진입하지 않고 일반 유튜브 메인 페이지(`youtube.com`)에 머무릅니다.
    *   키워드 검색을 통해 관련 분야의 동영상을 시청합니다. (시청 완료율 60% 이상 권장)
    *   정상적인 주기(하루 1~2회)로 좋아요를 누르고 채널을 구독합니다.
    *   다양한 카테고리의 동영상을 시청하여 시청 기록(History)과 관심사 쿠키를 누적합니다.

### 3.2 워밍업 시 네트워크 환경 가이드
> [!IMPORTANT]
> **Q. 워밍업 기간 유튜브 시청은 LTE로 해야 하나요, Wi-Fi 환경이어도 상관없나요?**
>
> **A. 일반 주거용 Wi-Fi 환경도 무방하며, 오히려 권장됩니다.**
> 일반 사용자가 하루 종일 LTE로만 유튜브를 고화질 시청하는 것은 무제한 요금제여도 부자연스럽습니다. 유튜브 시청, 좋아요, 구독 등의 **소비 행동(Consumption)**은 일반 주거용 인터넷/Wi-Fi 대역에서 진행하는 것이 훨씬 더 인간적(Human-like)인 신호입니다.
> 다만, 비디오 **업로드(Uploading)** 및 **권한 관리자 설정(Manager Administration)** 등의 쓰기 작업은 깨끗한 모바일 LTE IP 환경에서 동작해야 합니다.

## 4. API 비활성화 운영 (YouTube Data API v3 및 OAuth 디커플링)

유튜브 연좌제 확산의 주범 중 하나는 **구글 클라우드 콘솔의 OAuth 클라이언트 설정 및 Developer API 키 공유**입니다. 동일한 개발자 프로젝트나 API 키를 사용하는 모든 채널은 구글 내부 시스템에서 하나의 물리적 소유자(동일 조직)로 100% 매핑됩니다.

### 4.1 API 연동 생략 및 브라우저 자동화의 당위성
*   **OAuth 차단의 위험**: 특정 채널의 오남용으로 인해 개발자 프로젝트의 OAuth 토큰이 폐기되거나 경고를 받으면, 동일한 `client_secret.json`을 공유하는 모든 채널에 정지 및 도미노식 섀도우밴이 확산됩니다.
*   **브라우저 자동화(BROWSER_AUTO)의 안전성**: API를 거치지 않고, 격리된 크롬 브라우저를 통해 마치 사람이 유튜브 스튜디오 UI를 직접 클릭해 비디오를 올리는 것처럼 자동화하는 방식이 훨씬 안전합니다. 이 방식을 사용하면 어떠한 API 인증 흔적도 남지 않아 연좌제 고리가 완전히 파괴됩니다.
*   **데이터 분리**: 따라서 신규 채널 및 프로필 등록 시 필수적이지 않은 YouTube Data API v3 등록 및 OAuth 동의 절차를 선택적으로 건너뛰어(Skip) 브라우저 자동 업로더로만 구성할 수 있도록 지원합니다.

## 5. 요약 및 운영 수칙

1.  **1채널 1소유자(TIN_CAN) 원칙을 고수할 것.** 소유자는 최초 위임용으로만 사용하고 로그아웃(Ghosting).
2.  **관리자(CAPTAIN) 1개당 브랜드 채널 매칭 개수를 최대 3~5개로 제한할 것.**
3.  **신규 계정은 스마트폰으로 최초 5~6개 영상을 올리며 신뢰도(Trust Score)를 누적할 것.**
4.  **7일간의 워밍업 시 시청 기록(Cookies/History)은 일반 주거용 Wi-Fi를 통해 자연스럽게 쌓을 것.**
5.  **유튜브 Data API v3 연동은 과감히 건너뛰고(Skip), VLStudio의 브라우저 자동 업로드(BROWSER_AUTO) 모드를 우선하여 사용할 것.**
