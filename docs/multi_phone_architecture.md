# 멀티 핸드폰 프록시 아키텍처 (향후 확장 설계서)

본 문서는 향후 2대 이상의 안드로이드 스마트폰을 연결하여 대량의 영상을 병렬(다중)로 업로드하고 완벽한 IP 격리(연좌제 방어)를 구현하기 위한 시스템 확장 가이드라인입니다.

## 1. 기존 시스템의 한계 (순정 USB 테더링)
- 윈도우 OS는 여러 대의 USB 테더링 기기가 연결될 경우, 라우팅 테이블(Default Gateway) 충돌을 일으켜 가장 Metric 우선순위가 높은 1대의 기기로 모든 트래픽을 집중시킵니다.
- 따라서 영상 2개를 동시에 업로드하면 2개 채널이 모두 똑같은 1개의 공인 IP로 노출되어 연좌제에 즉시 걸립니다.

## 2. 해결책: Proxy App + ADB Forwarding
핸드폰의 네트워크(LTE)를 PC 윈도우 전체에 씌우지 않고, **특정 브라우저 창(Context)에만 씌우는 타겟팅 기법**입니다.

### 2.1 핸드폰 설정 (사전 준비)
1. **각 기기에 데이터 유심 개통**: IP 분리를 위해서는 기기별 독립된 통신사 회선이 필수입니다. (공기계 핫스팟 불가)
2. **프록시 앱 설치**: Android 기기에 `EveryProxy` 등 HTTP/SOCKS5 프록시 서버 앱을 설치합니다.
3. **프록시 서버 구동**: 앱 내에서 프록시 서버를 시작합니다. (예: `0.0.0.0:8080`)

### 2.2 백엔드 연결 로직 (ADB 포워딩)
PC와 핸드폰을 USB로 연결한 후, `adb forward` 명령을 통해 PC의 로컬 포트를 핸드폰 내부의 프록시 포트로 다이렉트 연결합니다.

```bash
# 1번 폰 (시리얼: PhoneA)
adb -s PhoneA forward tcp:10081 tcp:8080

# 2번 폰 (시리얼: PhoneB)
adb -s PhoneB forward tcp:10082 tcp:8080
```

### 2.3 브라우저 라우팅 (Playwright/Patchright)
업로드 큐 워커가 브라우저 Context를 생성할 때, 해당 채널에 할당된 폰의 로컬 포트를 프록시로 지정합니다.

```python
# 1번 폰을 사용하는 채널 A의 브라우저 띄우기
context_A = browser.new_context(
    proxy={"server": "http://127.0.0.1:10081"}
)

# 2번 폰을 사용하는 채널 B의 브라우저 띄우기
context_B = browser.new_context(
    proxy={"server": "http://127.0.0.1:10082"}
)
```

## 3. 프록시 기반 핑퐁(Ping-Pong) 로테이션 로직
핸드폰이 2대일 경우, IP 교체 대기시간(15초)을 `0초`로 만들 수 있습니다.

1. **작업 1**: 폰 A(프록시 10081)로 1번 영상 업로드.
2. **작업 2**: 폰 B(프록시 10082)로 2번 영상 업로드 시작.
3. **병렬 회전**: 폰 B가 2번 영상을 업로드하는 도중에, 백그라운드에서 폰 A는 비행기 모드를 토글(15초 소요)하여 새로운 IP를 획득.
4. **작업 3**: 폰 B의 업로드가 끝나면, 즉시 준비된 폰 A로 3번 영상 업로드. 폰 B는 비행기 모드 토글 진행.

이 구조를 도입하면 업로드 워커(Worker)는 쉴 틈 없이 돌아가게 되어 30개의 영상 대기열 처리 시간을 절반 이하로 단축시킵니다.
